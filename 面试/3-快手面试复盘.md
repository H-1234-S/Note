# 解释一下宏任务、微任务、raf

> raf 在浏览器下一帧绘制前执行

```js
console.log(1)
setTimeout(() => console.log(2),0)
requestAnimationFrame(() => console.log(3))
Promise.resolve.then(() => console.log(4))
console.log(5)
```

`requestAnimationFrame` 不是 `Event Loop` 的固定阶段，执行时机取决于浏览器的下一帧何时渲染

`requestAnimationFrame` 和 `setTimeout` 执行的先后顺序取决于浏览器下一次何时渲染

> 举个例子：如果 JS 一直在执行，浏览器根本没有时间渲染，因此 requestAnimationFrame 就一直不会执行
# 浏览器每一帧都在做什么

浏览器每 `16.67` 毫秒尝试生成一帧，但是浏览器每一帧做的事情是不固定的

理想情况下，一次渲染机会大致会经历：
```
执行一个宏任务（Task）
        ↓
清空所有微任务（Microtask）
        ↓
浏览器进入一次渲染机会
        ↓
执行所有 requestAnimationFrame 回调
        ↓
如有需要：
  Style（样式计算）
  Layout（重排）
  Paint（重绘）
  Composite（图层合成）
        ↓
提交给 GPU，等待显示器显示
```

因为 JavaScript、样式计算、布局、绘制等都运行在浏览器主线程上，浏览器不会中断正在执行的 JavaScript 去进行渲染，所以当 JS 长时间占用主线程时，浏览器只能错过一次又一次的渲染机会，从而产生掉帧和卡顿。
# useEffect、useLayoutEffect

# 场景题

``` js
import { useEffect, useState } from "react";

export function Demo() {
    const [value, setValue] = useState('')
    const [data, setData] = useState()
  
    useEffect(() => {
        fetch(`/api/shop?query=${value}`)
            .then(res => res.json())
            .then(result => {
                setData(result)
            })
    }, [value])
  
    return (
        <div>
            <input type="text" value={value} onChange={(e) => setValue(e.target.value)} />
        </div>
    )
}
```

>问有什么问题？

问题在于每次用户输入时都会发送 fetch 请求；还有竞态条件，网络请求是不可控的，也许后一个 fetch 请求先响应

> 怎么优化？

使用 AbortController 每次运行时先取消上一个 fetch；使用闭包解决竞态问题

``` js
useEffect(() => {
    let ignore = false;

    fetch(`/api/shop?query=${value}`)
        .then(res => res.json())
        .then(result => {
            if (!ignore) {
                setData(result);
            }
        });

    return () => {
        ignore = true;
    };
}, [value]);
```

> 每次运行 useEffect 都会创建一个全新的作用域；执行清理函数时会将旧作用域中的ignore更改为true
# Promise.all、Promise.allSettled

> Promise.all 全部成功才resolve，有一个失败则reject

> Promise.allSettled 全部完成才会 resolve，不会单独 reject

> Promise.race 以第一个完成的结果为标准

> Promise.any 以第一个fulilled，失败条件则全部失败才会reject
