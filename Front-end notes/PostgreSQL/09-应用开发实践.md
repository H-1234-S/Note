# 09. 应用开发实践

## 连接字符串

```text
postgresql://postgres:postgres@localhost:5432/study
```

生产环境不要把密码提交到代码仓库，使用环境变量：

```bash
DATABASE_URL="postgresql://app_user:secret@db.example.com:5432/app"
```

## Node.js 参数化查询

```js
import pg from 'pg';

const pool = new pg.Pool({
  connectionString: process.env.DATABASE_URL,
  max: 10
});

const { rows } = await pool.query(
  'SELECT id, email FROM users WHERE email = $1',
  [email]
);
```

## 连接池

每个请求新建连接是常见错误。应该复用连接池：

```js
const pool = new pg.Pool({
  connectionString: process.env.DATABASE_URL,
  max: 10,
  idleTimeoutMillis: 30_000,
  connectionTimeoutMillis: 2_000
});
```

## Prisma 示例

`schema.prisma`：

```prisma
datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

model User {
  id        BigInt   @id @default(autoincrement())
  email     String   @unique
  name      String
  createdAt DateTime @default(now()) @map("created_at")

  @@map("users")
}
```

迁移：

```bash
npx prisma migrate dev --name init
```

## 迁移原则

- 每次结构变化都写迁移，不直接手改生产库。
- 大表改字段要考虑锁和回填成本。
- 先加可空字段，再回填，再加 `NOT NULL`，通常比一步到位稳。
- 删除字段前先确认应用不再读取。

示例：安全添加字段。

```sql
ALTER TABLE users ADD COLUMN phone TEXT;

UPDATE users
SET phone = ''
WHERE phone IS NULL;

ALTER TABLE users
ALTER COLUMN phone SET NOT NULL;
```

## 常见坑

- 长事务导致 VACUUM 无法清理旧版本。
- 连接池配置过大，把数据库连接打满。
- 对低选择性字段盲目建索引。
- 用 `OFFSET` 做深分页。
- 忘记给外键列建索引，导致 JOIN 或级联操作慢。
- 在应用层拼接 SQL，造成 SQL 注入。

## 推荐目录结构

```text

  migrations/
  seeds/
  queries/
```
