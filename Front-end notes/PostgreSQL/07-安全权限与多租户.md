# 07. 安全、权限与多租户

## 角色

PostgreSQL 用角色管理登录和权限。

```sql
CREATE ROLE app_user LOGIN PASSWORD 'change-me';
CREATE ROLE readonly LOGIN PASSWORD 'change-me';
```

## 授权

```sql
GRANT CONNECT ON DATABASE study TO app_user;
GRANT USAGE ON SCHEMA public TO app_user;
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO app_user;
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO app_user;
```

只读角色：

```sql
GRANT CONNECT ON DATABASE study TO readonly;
GRANT USAGE ON SCHEMA public TO readonly;
GRANT SELECT ON ALL TABLES IN SCHEMA public TO readonly;
```

为未来新表设置默认权限：

```sql
ALTER DEFAULT PRIVILEGES IN SCHEMA public
GRANT SELECT ON TABLES TO readonly;
```

## 最小权限原则

生产中常见角色：

- 迁移角色：允许 DDL，例如 `CREATE / ALTER / DROP`。
- 应用角色：允许必要的 DML，例如 `SELECT / INSERT / UPDATE / DELETE`。
- 只读角色：只允许查询。
- 管理角色：只给少数人使用。

## Schema 隔离

```sql
CREATE SCHEMA tenant_a;
CREATE SCHEMA tenant_b;
```

Schema 隔离简单直观，但租户非常多时管理成本会上升。

## 行级安全 RLS

适合共享表多租户：

```sql
CREATE TABLE projects (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  tenant_id TEXT NOT NULL,
  name TEXT NOT NULL
);

ALTER TABLE projects ENABLE ROW LEVEL SECURITY;

CREATE POLICY tenant_isolation ON projects
USING (tenant_id = current_setting('app.tenant_id'));
```

应用连接后设置当前租户：

```sql
SET app.tenant_id = 'tenant_001';

SELECT *
FROM projects;
```

## 防 SQL 注入

错误示例：拼接用户输入。

```js
const sql = `SELECT * FROM users WHERE email = '${email}'`;
```

正确示例：参数化查询。

```js
const result = await client.query(
  'SELECT * FROM users WHERE email = $1',
  [email]
);
```

练习：

1. 创建一个只读角色。
2. 给 `projects` 表启用 RLS。
3. 用参数化查询重写拼接 SQL。
