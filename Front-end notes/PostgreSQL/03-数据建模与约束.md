# 03. 数据建模与约束

## 常用数据类型

- 整数：`SMALLINT`、`INTEGER`、`BIGINT`
- 精确小数：`NUMERIC(12, 2)`，适合金额
- 字符串：`TEXT`、`VARCHAR(n)`
- 布尔：`BOOLEAN`
- 时间：`DATE`、`TIMESTAMP`、`TIMESTAMPTZ`
- 枚举：`CREATE TYPE ... AS ENUM`
- 半结构化：`JSONB`
- 数组：`TEXT[]`、`INTEGER[]`
- UUID：`UUID`

金额不要用浮点数：

```sql
price NUMERIC(12, 2) NOT NULL
```

## 主键

```sql
CREATE TABLE products (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  name TEXT NOT NULL
);
```

## 唯一约束

```sql
CREATE TABLE accounts (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  email TEXT NOT NULL,
  CONSTRAINT accounts_email_key UNIQUE (email)
);
```

## 检查约束

```sql
CREATE TABLE order_items (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  quantity INTEGER NOT NULL CHECK (quantity > 0),
  unit_price NUMERIC(12, 2) NOT NULL CHECK (unit_price >= 0)
);
```

## 外键

```sql
CREATE TABLE orders (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  user_id BIGINT NOT NULL REFERENCES users(id),
  total_amount NUMERIC(12, 2) NOT NULL CHECK (total_amount >= 0),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

级联删除要谨慎：

```sql
CREATE TABLE notes (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  user_id BIGINT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  title TEXT NOT NULL
);
```

## Schema

Schema 是数据库内的命名空间。生产中常见用法：

```sql
CREATE SCHEMA app;
CREATE SCHEMA audit;

CREATE TABLE app.users (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  email TEXT NOT NULL UNIQUE
);
```

## 范式和反范式

基本原则：

- 一类实体一张表。
- 重复出现的集合通常拆表。
- 通过外键表达关系。
- 查询性能真的需要时再反范式，例如缓存统计字段。

反范式示例：

```sql
ALTER TABLE users
ADD COLUMN order_count INTEGER NOT NULL DEFAULT 0;
```

这个字段需要应用逻辑、触发器或定时任务维护一致性。

练习：

1. 为博客系统设计 `users / posts / comments / tags / post_tags`。
2. 给 `posts.status` 加检查约束，只允许 `draft / published / archived`。
3. 思考哪些字段适合建唯一约束。
