# 05. 索引与查询优化

## 索引是什么

索引帮助数据库更快定位数据，但会增加写入成本和存储占用。不是所有列都应该建索引。

## B-tree 索引

默认索引类型，适合等值、范围、排序：

```sql
CREATE INDEX idx_users_email ON users (email);
CREATE INDEX idx_orders_created_at ON orders (created_at DESC);
```

组合索引遵循“左前缀”思路：

```sql
CREATE INDEX idx_orders_user_created ON orders (user_id, created_at DESC);
```

适合：

```sql
SELECT *
FROM orders
WHERE user_id = 1
ORDER BY created_at DESC
LIMIT 20;
```

## 唯一索引

```sql
CREATE UNIQUE INDEX idx_users_lower_email
ON users (lower(email));
```

## 部分索引

只索引部分数据：

```sql
CREATE INDEX idx_orders_unpaid
ON orders (created_at)
WHERE status = 'unpaid';
```

## 表达式索引

```sql
CREATE INDEX idx_users_email_domain
ON users ((split_part(email, '@', 2)));
```

查询要写成相同表达式：

```sql
SELECT *
FROM users
WHERE split_part(email, '@', 2) = 'example.com';
```

## GIN 索引

适合 JSONB、数组、全文搜索：

```sql
CREATE INDEX idx_events_payload_gin
ON events
USING gin (payload);

SELECT *
FROM events
WHERE payload @> '{"type": "signup"}';
```

## BRIN 索引

适合超大表中和物理写入顺序相关的字段，例如时间：

```sql
CREATE INDEX idx_logs_created_brin
ON logs
USING brin (created_at);
```

## EXPLAIN

```sql
EXPLAIN (ANALYZE, BUFFERS)
SELECT *
FROM orders
WHERE user_id = 1
ORDER BY created_at DESC
LIMIT 20;
```

重点看：

- `Seq Scan`：顺序扫描，表小或返回比例高时正常。
- `Index Scan`：通过索引定位，再访问表。
- `Index Only Scan`：只读索引即可返回结果，但依赖可见性信息。
- `Rows Removed by Filter`：过滤掉多少行。
- `Buffers`：读了多少缓存和磁盘页。
- 估算行数和真实行数差异是否过大。

## 统计信息

```sql
ANALYZE orders;
```

表大量变化后，统计信息不准会影响查询计划。

## 优化顺序

1. 先确认慢查询和业务目标。
2. 用 `EXPLAIN (ANALYZE, BUFFERS)` 看真实计划。
3. 检查过滤条件、JOIN 条件、排序字段。
4. 增加或调整索引。
5. 必要时改写 SQL 或调整数据模型。

练习：

1. 给订单列表查询建立组合索引。
2. 比较 `OFFSET` 分页和游标分页。
3. 给 JSONB 字段建立 GIN 索引并查询。
