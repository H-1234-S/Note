# 08. 备份、恢复与运维

## 逻辑备份

备份一个数据库：

```bash
pg_dump -h localhost -U postgres -d study -F c -f study.dump
```

恢复：

```bash
createdb -h localhost -U postgres study_restore
pg_restore -h localhost -U postgres -d study_restore study.dump
```

导出 SQL 文本：

```bash
pg_dump -h localhost -U postgres -d study -f study.sql
```

恢复 SQL：

```bash
psql -h localhost -U postgres -d study_restore -f study.sql
```

## 全局对象备份

角色、表空间等不属于单个数据库：

```bash
pg_dumpall -h localhost -U postgres --globals-only > globals.sql
```

## VACUUM 和 MVCC

PostgreSQL 使用 MVCC。更新和删除不会立刻覆盖旧版本，而是产生“死元组”。`VACUUM` 负责清理。

```sql
VACUUM (VERBOSE, ANALYZE) orders;
```

日常依赖 Autovacuum，但要监控它是否跟得上写入量。

## WAL

WAL 是预写日志，用于崩溃恢复、复制和时间点恢复。理解 WAL 有助于理解为什么磁盘、检查点、复制延迟会影响数据库表现。

## 复制入门

常见形态：

- 物理复制：主库到只读副本，适合高可用和读扩展。
- 逻辑复制：按表复制数据，适合数据同步、在线迁移、异构系统集成。

逻辑发布示例：

```sql
CREATE PUBLICATION app_pub FOR TABLE users, orders;
```

订阅示例：

```sql
CREATE SUBSCRIPTION app_sub
CONNECTION 'host=primary port=5432 dbname=study user=replicator password=secret'
PUBLICATION app_pub;
```

## 监控常用视图

```sql
SELECT pid, state, query, query_start
FROM pg_stat_activity
ORDER BY query_start;
```

```sql
SELECT relname, n_live_tup, n_dead_tup, last_vacuum, last_autovacuum
FROM pg_stat_user_tables
ORDER BY n_dead_tup DESC;
```

```sql
SELECT query, calls, total_exec_time, mean_exec_time
FROM pg_stat_statements
ORDER BY total_exec_time DESC
LIMIT 10;
```

`pg_stat_statements` 需要启用扩展：

```sql
CREATE EXTENSION IF NOT EXISTS pg_stat_statements;
```

## 生产检查清单

- 是否定期备份，并演练恢复。
- 是否设置合理连接数和连接池。
- 是否监控慢查询、锁等待、磁盘、WAL、复制延迟。
- 是否有迁移回滚方案。
- 是否避免长事务。
- 是否给应用角色最小权限。

2. 查询当前数据库活动连接。
3. 找出死元组最多的表。
