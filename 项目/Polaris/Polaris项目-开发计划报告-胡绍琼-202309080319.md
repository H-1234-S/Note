## 1. 项目概述

Polaris 是一个 AI 驱动的浏览器端在线 IDE（集成开发环境）。项目的核心目标是构建一个"让用户、AI Agent、代码编辑器、预览环境和 GitHub 围绕同一份项目文件系统高效协作"的工作平台。

用户登录后可创建或导入项目，在线编辑代码（CodeMirror 6），通过 WebContainer 在浏览器中运行项目预览，并与 AI Agent 对话让 AI 自动读写项目文件。系统采用事件驱动 + 实时数据架构，通过 Convex 实现数据实时同步，Inngest 编排后台长任务（AI 消息处理、GitHub 导入/导出）。

## 2. 实施总计划

### 2.1 开发过程

本项目采用**特征驱动开发（Feature-Driven Development）**与**敏捷迭代**相结合的开发方法。

项目按 Feature（业务能力）组织代码结构（`src/features/projects`、`editor`、`conversations`、`preview`），每个 Feature 自包含组件、Hooks 和业务逻辑。开发遵循以下流程：

1. **需求分析与技术选型**（第 1 周）：确认功能清单，评审技术栈（Next.js + Convex + Inngest + AI SDK），产出需求规格说明书
2. **架构与数据库设计**（第 2-3 周）：设计系统分层架构、Convex Schema（projects/files/conversations/messages 四表）、UI 原型
3. **核心功能开发**（第 4-9 周）：按 Feature 并行推进，依次完成认证、项目管理、文件系统、编辑器、AI 对话、预览、GitHub 同步
4. **测试与优化**（第 10-11 周）：集成测试→性能测试→安全审计→用户验收测试
5. **部署交付**（第 12 周）：生产环境部署、用户培训、文档交付、试运行

### 2.2 系统设计

**总体架构分层：**

```text
┌─────────────────────────────────────────────────┐
│               Next.js App Router                 │
│         (页面路由 + API Route 薄入口)              │
├─────────────────────────────────────────────────┤
│             Feature Hooks 层                      │
│   (useProjects / useFiles / useConversations)     │
├──────────────┬────────────────┬─────────────────┤
│   Convex     │     Inngest    │   WebContainer  │
│ 实时数据库    │  后台任务编排   │   浏览器预览     │
│ (公开API)    │  (消息/GitHub)  │                 │
├──────────────┼────────────────┼─────────────────┤
│ Convex       │  AI Agent      │  CodeMirror 6   │
│ system 内部  │  + File Tools  │  在线编辑器      │
│              │                │                 │
└──────────────┴────────────────┴─────────────────┘
```

**技术选型：**

| 层次 | 技术选型 | 选型理由 |
|------|----------|----------|
| 前端框架 | Next.js App Router | 页面路由 + API Route 一体化，支持 Serverless 部署 |
| 认证服务 | Clerk | 开箱即用的 GitHub OAuth，与 Convex 深度集成 |
| 数据库 | Convex | 实时同步能力，前端 Hooks 直接订阅数据变化 |
| 后台任务 | Inngest | 事件驱动编排，支持长任务拆分、失败重试、可取消 |
| AI 能力 | Vercel AI SDK + DeepSeek | Agent 工具调用、多轮对话、流式响应 |
| 编辑器 | CodeMirror 6 | 模块化架构，支持自定义 Extension |
| 预览运行 | WebContainer | 浏览器沙箱运行 Node.js，无需服务端容器 |
| 状态管理 | Zustand | 管理编辑器 Tabs 等客户端 UI 状态 |
| 错误追踪 | Sentry | 前端 + 后端 + Inngest 全链路监控 |

**核心数据模型：**

| 表名 | 关键字段 | 说明 |
|------|----------|------|
| `projects` | name, ownerId, settings, importStatus, exportStatus | 项目聚合根，所有数据通过 projectId 关联 |
| `files` | projectId, parentId, name, type, content, storageId | 扁平文件表，parentId 表达层级，content/storageId 分离文本与二进制 |
| `conversations` | projectId, title, updatedAt | AI 会话，归属项目 |
| `messages` | conversationId, projectId, role, content, status | 消息冗余 projectId 便于项目级状态查询 |
