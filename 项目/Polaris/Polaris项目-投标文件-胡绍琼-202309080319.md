### 四、技术方案摘要

#### 4.1 项目理解

Polaris 是一个 AI 驱动的浏览器在线 IDE，核心目标是：**让用户、AI Agent、代码编辑器、预览环境和 GitHub 围绕同一份项目文件系统高效协作**。

与普通 CRUD 管理后台或聊天应用不同，Polaris 需要将"项目文件系统、AI 对话、代码编辑、运行预览、GitHub 同步"组织到统一的 `projectId` 上下文中，实现多模块联动。

#### 4.2 系统总体架构

```text
用户 → Next.js App Router 页面与组件
        ↓
    Feature Hooks (useProjects / useFiles / useConversations)
        ↓
    ┌───────────────┬──────────────────┬─────────────────┐
    ↓               ↓                  ↓                 ↓
Convex 公开 API  Next.js API Routes  Zustand Store    WebContainer
    ↓               ↓                                  (浏览器预览)
Convex 数据库    Inngest 后台任务
    ↑               ↓
system 内部函数 → AI Agent + Tools
                    ↓
              Convex 数据库/Storage
```

**技术选型：**

| 层级 | 技术 | 说明 |
|------|------|------|
| App 框架 | Next.js App Router | 页面路由、API Route |
| 认证 | Clerk | GitHub OAuth、多平台登录 |
| 数据库 | Convex | 实时同步、关系型查询 |
| 后台任务 | Inngest | 长任务编排、失败重试、可取消 |
| AI | Vercel AI SDK + DeepSeek | Agent 工具调用、多轮对话 |
| 编辑器 | CodeMirror 6 | 语法高亮、补全、Ghost Text |
| 预览 | WebContainer | 浏览器内运行 Dev Server |
| 状态管理 | Zustand | 编辑器 Tabs 状态 |
| 错误追踪 | Sentry | 全链路错误监控 |

#### 4.3 核心功能模块

| 模块 | 主要功能 | 实现方式 |
|------|----------|----------|
| 用户认证 | 注册/登录、GitHub OAuth、会话管理 | Clerk + Convex Auth |
| 项目管理 | 新建/导入/导出、Prompt 创建、配置命令 | Next.js + Convex + Inngest |
| 文件系统 | 层级目录、文件CRUD、文本/二进制分离 | Convex files 表（扁平+parentId） |
| 在线编辑器 | 代码编辑、语法高亮、AI 补全、快速编辑 | CodeMirror 6 + 自定义 Extension |
| AI 对话 | Agent 多轮对话、文件工具调用、状态管理 | Vercel AI SDK + Inngest Agent Kit |
| 在线预览 | 浏览器安装依赖、启动 Dev Server | WebContainer singleton |
| GitHub 同步 | 导入仓库（tree→files）、导出项目（files→tree→commit）| Octokit + Git Blob/Tree API |
