## 1. 数据模型必须补充的字段

### UsageRecord 表 - 支持额度追踪
```prisma
model UsageRecord {
  // 新增字段
  projectId       String?
  project         Project? @relation(fields: [projectId], references: [id], onDelete: SetNull)
  quotaType       String?  // daily_generation_count
  quotaConsumed   Int?     // 每次生成消耗 1
  
  @@index([userId, quotaType, recordedAt])
}
```

### GenerationJob 表 - 支持 Resume 重试
```prisma
model GenerationJob {
  // 新增字段
  completedSteps Json?  // {"storyboard": true, "audio": ["scene1"], "timeline": false}
  currentStep    String? // storyboard | audio | timeline | render
}
```

### Scene 表 - 补充 TDD 设计字段
```prisma
model Scene {
  // 新增字段
  sceneType     String? // title, concept, bullet_list, process
  visualJson    Json?   // 可视化结构
  captionsJson  Json?   // 字幕数组
}
```

## 2. 性能目标调整（现实化）

### TDD 文档中的目标（过于乐观）
- ❌ 3分钟视频生成 P75 ≤ 8分钟

### 调整后的目标
- ✅ 3分钟视频生成 P75 ≤ 10分钟
- ✅ 3分钟视频生成 P95 ≤ 15分钟

**理由**：
- LLM 生成 ~10-15s
- TTS 10个scene 并发 ~2-3分钟
- Remotion 渲染 3分钟视频 ~6-9分钟
- 状态更新、网络传输 ~30-60s
- **总计**：9-13分钟

## 5. Asset 复用隐患解决

### 方案 A（推荐）：多对多关联表
```prisma
model ProjectAsset {
  id        String @id @default(cuid())
  projectId String
  assetId   String
  role      String // audio | video | thumbnail
  @@unique([projectId, assetId, role])
}
```

### 方案 B（简单）：引用计数
```prisma
model Asset {
  referenceCount Int @default(1)
  // 使用时+1，删除时-1
}
```

**生产环境用 A，开发可先用 B**
