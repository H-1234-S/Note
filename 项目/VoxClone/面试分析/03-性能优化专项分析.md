# 性能优化专项分析

> 按三个维度深度扫描：渲染/计算优化、网络/数据流优化、打包/构建优化

---

## 一、渲染/计算优化

### ✅ 已实现的优化

| 优化点                  | 位置                                                              | 说明                                                                                            |
| -------------------- | --------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| **Selector 精准订阅**    | `text-input-panel.tsx:29-31`                                    | `useStore(form.store, selector)` 仅订阅需要的字段，`text` 变化不会导致 `VoiceSelector` 和 `SettingsPanel` 重渲染 |
| **useMemo 缓存计算**     | `use-voice-avatar.ts:6-10`                                      | DiceBear 头像生成是纯计算，使用 `useMemo` 避免每次渲染重新创建 SVG                                                 |
| **防抖搜索**             | `voices-toolbar.tsx:22-25`                                      | 使用 `use-debounce` 库，300ms 防抖 URL query 参数变更，避免每次输入都触发网络请求 + URL 更新                            |
| **动态导入重型库**          | `use-audio-recorder.ts:108-110`                                 | `import("recordrtc")` 动态加载，仅在用户点击"开始录音"时才加载 RecordRTC，初始 Bundle 不包含                           |
| **条件渲染 + CSS 控制显隐**  | `voice-preview-panel.tsx:81-98`                                 | 使用 `opacity-0` + `transition-opacity` 而非条件卸载，避免 WaveSurfer 反复创建/销毁                            |
| **useCallback 稳定引用** | `use-audio-recorder.ts`, `use-wavesurfer.ts`, `use-checkout.ts` | 所有暴露给 useEffect 依赖数组的回调都使用 useCallback 包裹                                                     |

### ⚠️ 可优化但尚未实现

| 优化点                       | 问题描述                                                                                                   | 建议方案                                                     |
| ------------------------- | ------------------------------------------------------------------------------------------------------ | -------------------------------------------------------- |
| **虚拟列表（Virtual List）**    | `SettingsPanelHistory` 中 `generations.map()` 直接渲染所有历史记录。当用户积累数百条记录时，DOM 节点数量会显著影响滚动性能                  | 使用 `@tanstack/react-virtual` 或 `react-window` 对历史列表做虚拟滚动 |
| **大文本输入的防抖**              | `TextInputPanel` 中 `text` 每次按键都触发 TanStack Form 的 state 更新，当文本长度接近 5000 字符极限时，每次 onChange 都会触发重渲染和费用重算 | 对 `text` 字段使用防抖，或使用 `useDeferredValue` 延迟费用计算            |
| **React.memo 缺失**         | `VoiceCard`、`SettingsPanelHistory` 的子项没有 `React.memo` 包裹。列表中某一项 hover 可能导致整列表重渲染                       | 对列表子组件添加 `React.memo` + `useCallback` 传递回调               |
| **WaveSurfer 懒加载**        | WaveSurfer.js（~200KB）在 `voice-preview-panel.tsx` 中被同步导入（via `useWaveSurfer` hook），即使用户可能不打开详情页         | 对 `useWaveSurfer` 做动态 import，仅在详情页渲染时才加载                 |
| **音频播放的 AbortController** | `VoicePreviewMobile` 中 `<audio>` 切换 URL 时没有 AbortController，先前的音频可能还在缓冲                                | 添加 AbortController 取消旧的音频加载                              |

## 二、网络/数据流优化

### ✅ 已实现的优化

| 优化点                                | 位置                                          | 说明                                                                |
| ---------------------------------- | ------------------------------------------- | ----------------------------------------------------------------- |
| **Server-Side Prefetch + Hydrate** | `text-to-speech/page.tsx:15-17`             | 服务端并行 `prefetch()` 语音列表和生成记录，客户端 `useSuspenseQuery` 直接命中缓存，0 网络请求 |
| **并行查询**                           | `tts-voices-context.tsx` → `voice.ts:35-67` | 后端 `Promise.all([customQuery, systemQuery])` 并行查询两表，而非串行查询        |
| **useSuspenseQueries 并行**          | `text-to-speech-detail-view.tsx:22-29`      | 详情页同时需要 generation 数据和 voices 数据，使用 `useSuspenseQueries` 并行发起     |
| **Query Stale Time**               | `query-client.ts:11`                        | `staleTime: 30 * 1000` — 30 秒内标记为新鲜，避免短时间内重复请求（如快速切 Tab 又切回来）     |
| **HTTP Batching**                  | `trpc/client.tsx:49`                        | 使用 `httpBatchLink`，多个并行的 tRPC 查询自动合并为一个 HTTP 请求                   |
| **音频缓存策略**                         | `api/audio/[generationId]/route.ts:39`      | `Cache-Control: private, max-age=3600` — 生成的音频 URL 浏览器缓存 1 小时     |
| **URL 状态同步**                       | `voices-toolbar.tsx:16-18`                  | 搜索 query 通过 `nuqs` 同步到 URL query string，支持分享链接、浏览器前进后退            |

### ⚠️ 可优化但尚未实现

| 优化点 | 问题描述 | 建议方案 |
|--------|---------|---------|
| **乐观更新（Optimistic Update）** | Voice 删除操作使用 `mutation` 后 invalidate 整个 `voices.getAll` 查询，需要等待服务端响应 + 重新请求列表才更新 UI | 使用 `onMutate` 在发送请求前立即从缓存中移除，配合 `onError` 回滚 |
| **增量数据加载 / 分页** | `generations.getAll` 查询加载全部历史记录，无分页。当用户生成数千条记录时，首次加载全部数据 | 添加 tRPC cursor-based 分页或 `useInfiniteQuery` |
| **Streaming 响应** | TTS 生成是同步等待 AI 引擎返回完整 ArrayBuffer 后才响应。对于长文本生成（几十秒），用户看到的是长时间无反馈的 Loading | 考虑使用 ReadableStream + 分块传输，让用户边生成边听到前几秒的音频 |
| **请求去重（Request Deduplication）** | 虽然 tRPC batching 合并了同批次的请求，但如果两个组件在不同渲染周期分别触发同一个 query，React Query 默认会去重，但需确认 `staleTime` 设置合理 | 对高频查询适当延长 `staleTime` |

## 三、打包/构建优化

### ✅ 已实现的优化

| 优化点 | 位置 | 说明 |
|--------|------|------|
| **Tree Shaking - Sentry 日志移除** | `next.config.ts:46-47` | `treeshake: { removeDebugLogging: true }` — 生产构建自动移除 `Sentry.logger.info` 等调试日志 |
| **Source Map 上传** | `next.config.ts:28` | `widenClientFileUpload: true` — 上传更完整的 source map 到 Sentry，生产错误堆栈可精确到行 |
| **tRPC Sentry 中间件** | `trpc/init.ts:23-27` | `Sentry.trpcMiddleware({ attachRpcInput: true })` — 自动捕获 tRPC 错误并附带到输入参数 |
| **动态导入** | `use-audio-recorder.ts:108` | RecordRTC（~50KB）按需加载 |
| **server-only / client-only** | `trpc/server.tsx` 使用 `server-only` | 防止服务端代码泄漏到客户端 Bundle |

### ⚠️ 可优化但尚未实现

| 优化点 | 问题描述 | 建议方案 |
|--------|---------|---------|
| **WaveSurfer 拆分** | WaveSurfer.js 全量引入 ~200KB，但实际只用了录制插件和基础播放。未使用的插件（如 Timeline、Spectrogram、Regions 等）也被打包 | 仅导入需要的模块：`import WaveSurfer from 'wavesurfer.js/dist/wavesurfer.esm.js'` |
| **locale-codes 全量引入** | `locale-codes` 包含 400+ 语言的所有元数据，在 `voice-create-form.tsx:25` 中全量引入仅为了构建语言下拉选择器 ~150KB | 在服务端筛选出常用语言列表，或使用静态 JSON 文件替换 |
| **Lucide Icons Tree Shaking** | 虽然 `lucide-react` 本身支持 tree-shaking，但项目引入了 20+ 个图标。可验证 Tree Shaking 是否真正生效 | `npm run build && npx @next/bundle-analyzer` 分析实际打包结果 |
| **react-dropzone** | ~30KB，仅在 Voice Create Dialog 中使用。此功能低频使用（创建声音），可考虑动态导入 | `const { useDropzone } = await import("react-dropzone")` |
| **Sentry Tunnel Route** | 已配置 `tunnelRoute: "/monitoring"` 绕过广告拦截器，但增加了服务端负载 | 评估 Sentry 错误量，必要时降低采样率 `tracesSampleRate` |

## 五、面试话术建议

当面试官问"你在项目中做过哪些性能优化"时，可以按以下优先级回答：

1. **"我们通过 TanStack React Form 的 Selector 模式，实现了表单 4 个子组件的精准渲染隔离"** → 展示对 React 渲染机制的理解
2. **"SSR 阶段预取数据 → 脱水注入客户端 → useSuspenseQuery 命中缓存，用户看到页面时数据已就绪"** → 展示全栈性能优化的能力
3. **"tRPC 的 httpBatchLink 自动合并多个并行查询为一个 HTTP 请求，减少往返延迟"** → 展示对网络层优化的理解
4. **"重型库按需加载：RecordRTC 50KB 仅在用户点击录音时才动态 import"** → 展示 Bundle 优化的实战经验
